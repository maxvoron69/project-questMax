# План: Перенос логики квеста на сервер

## Контекст

### Текущее состояние
- Логика квеста находится на клиенте (JavaScript в JSP)
- Имя передаётся через URL-параметры (`?name=...`) между всеми страницами
- Состояние игры НЕ хранится на сервере — каждая JSP — статичный файл
- **Уязвимость**: можно открыть `quest4.jsp` напрямую и увидеть победу
- `RestartServlet` уже инвалидирует сессию (исправлено ранее)

### Требуемое состояние
- Единый сервлет для всех шагов квеста
- Состояние игры хранится в HTTP-сессии
- Сервер определяет следующий шаг на основе текущего шага и выбора игрока
- JSP становятся шаблонами, контент определяется сервером
- Прямой доступ к `quest*.jsp` без прохождения предыдущих шагов невозможен

## Архитектура

### 1. Enum `QuestStep` — состояния игры

```
PROLOGUE → ROUND_1 → ROUND_2 → ROUND_3 → VICTORY
   ↓          ↓         ↓         ↓
DEFEAT     DEFEAT_1  DEFEAT_2  DEFEAT_3
```

Каждый шаг содержит:
- `title` — заголовок для JSP
- `message` — текст сцены
- `option1Text` / `option2Text` — тексты кнопок
- `option1NextStep` / `option2NextStep` — следующий шаг при выборе

### 2. Класс `GameSession` — состояние в сессии

Хранится как атрибут сессии (`"gameSession"`):
- `playerName` — String
- `currentStep` — QuestStep
- `timestamp` — для отладки

### 3. Сервлет `QuestServlet` — единая точка входа

- `@WebServlet("/quest")`
- **GET `/quest`** — отображает текущий шаг из сессии
  - Если сессия пуста или шаг PROLOGUE → редирект на `/index.jsp`
  - Если шаг в сессии → рендерит шаблон с контентом шага
- **POST `/quest`** — обработка выбора
  - Принимает `choice` (1 или 2) из формы
  - Определяет следующий шаг по логике
  - Обновляет сессию
  - Редирект на `/quest` (POST/Redirect/Get pattern)

### 4. JSP-шаблон `quest.jsp` — единая страница для всех шагов

Динамически рендерит:
- Заголовок и текст из `QuestStep`
- Кнопки с POST-формой (choice=1 / choice=2)
- Имя игрока из сессии

### 5. Страницы поражения — `defeat.jsp` (обобщённая)

Единая страница поражения с динамическим заголовком и текстом из `QuestStep`.

> **Решение:** Одна обобщённая `defeat.jsp` вместо трёх отдельных (defeat.jsp, defeat1.jsp, defeat2.jsp).

### 6. Обновлённый `InitServlet`

- Инициализирует `GameSession` в сессии
- Устанавливает `currentStep = ROUND_1`
- Инкрементирует `totalGames` через `StatisticsManager` (отдельно от GameSession)
- Редирект на `/quest`

> **Решение:** `StatisticsManager` оставить отдельно — `totalGames` это глобальная метрика приложения, не состояния конкретной игры.

### 7. Обновлённый `RestartServlet`

- Уже инвалидирует сессию (исправлено ранее)
- Редирект на `/index.jsp`

## Детали QuestServlet

```java
@WebServlet("/quest")
public class QuestServlet extends HttpServlet {
    
    protected void doGet(...) {
        GameSession session = getGameSession(req);
        if (session == null || session.getCurrentStep() == QuestStep.PROLOGUE) {
            resp.sendRedirect(req.getContextPath() + "/index.jsp");
            return;
        }
        req.setAttribute("gameSession", session);
        req.getRequestDispatcher("/quest.jsp").forward(req, resp);
    }
    
    protected void doPost(...) {
        int choice = Integer.parseInt(req.getParameter("choice"));
        GameSession gameSession = getGameSession(req);
        
        QuestStep currentStep = gameSession.getCurrentStep();
        QuestStep nextStep = getNextStep(currentStep, choice);
        
        gameSession.setCurrentStep(nextStep);
        
        req.setAttribute("gameSession", gameSession);
        req.getRequestDispatcher("/quest.jsp").forward(req, resp);
    }
    
    private QuestStep getNextStep(QuestStep step, int choice) {
        switch (step) {
            case ROUND_1: return choice == 1 ? ROUND_2 : DEFEAT;
            case ROUND_2: return choice == 1 ? ROUND_3 : DEFEAT;
            case ROUND_3: return choice == 1 ? VICTORY : DEFEAT;
            default: return step;
        }
    }
    
    private GameSession getGameSession(HttpServletRequest req) {
        HttpSession httpSession = req.getSession();
        GameSession gs = (GameSession) httpSession.getAttribute("gameSession");
        if (gs == null) {
            gs = new GameSession("неизвестно", QuestStep.PROLOGUE);
            httpSession.setAttribute("gameSession", gs);
        }
        return gs;
    }
}
```

public class InitServlet extends HttpServlet {

        String playerName = req.getParameter("name");

            playerName = "неизвестно";
        }
        
        HttpSession session = req.getSession(true);

## Риски и замечания

- `StatisticsManager` хранит `totalGames` отдельно от `GameSession`. Можно либо оставить (статистика глобальная), либо объединить. Рекомендую оставить — `totalGames` — это метрика приложения, а не конкретной игры.
- JSP использует JSTL (`<c:url>`, `${}`) — нужно убедиться, что JSTL подключён (уже есть в pom.xml).
- `javax.servlet` API (не Jakarta) — проект на Java EE, всё корректно.
